- El archivo vive en `noBackupFilesDir`.

## Defectos hallados por lint/pruebas y corregidos
- `InputStream.readNBytes` es API 33 (minSdk 31) → lectura acotada propia con prueba.
- Un reintento tras fallar la escritura inicial habría creado un segundo DataStore sobre el mismo archivo → se reutiliza la instancia.
- Un estado resultante inválido se habría informado como `RecoveryRequired` → ahora es `InvalidInput`.

## Limitaciones / pendiente
- La transferencia dispositivo a dispositivo (D2D) no se pudo probar (un solo emulador, sin segundo equipo); la protección se apoya en `noBackupFilesDir` + reglas, como pide DATA §4. Registrar en T10 con un equipo físico y en Samsung.
- El borrado de la clave al limpiar datos se observó en Android 14; repetir en API 31/35+ (T10).
- No se probó R8 en ejecución (APK release sin firmar; la regla de Protobuf lite se valida en T10).
- Reiniciar el teléfono tras el primer desbloqueo y modo avión → T10.
- `ReadError` reintentable se cubre en JVM (Keystore no disponible, directorio sin escritura); no se forzó en el dispositivo.
